Docker Container DevOps Virtualisierung

Docker ist eine der wichtigsten Technologien der letzten Jahre und hat die Software-Entwicklung revolutioniert. In diesem Artikel erkläre ich dir, was Docker ist, warum es so nützlich ist und wie du es praktisch einsetzen kannst.

Was ist Docker?

Docker ist eine Plattform zur Containerisierung von Anwendungen. Stell dir Container wie standardisierte Schiffscontainer vor - egal was drin ist, sie haben alle die gleiche Form und passen überall hin.

Das Problem vor Docker:

  • "Es funktioniert auf meinem Rechner!" - Entwicklerproblem
  • Unterschiedliche Entwicklungsumgebungen
  • Komplexe Deployment-Prozesse
  • Abhängigkeiten-Konflikte

Wie funktioniert Containerisierung?

Container vs Virtuelle Maschinen:

Aspekt Container (Docker) Virtuelle Maschine (VM)
Startzeit Sekunden Minuten
Ressourcenverbrauch Sehr gering Hoch
Größe MB GB
Isolation Prozess-Level Hardware-Level

Docker-Grundbegriffe

Docker Image:

Eine Momentaufnahme deiner Anwendung mit allen Abhängigkeiten. Wie ein Rezept oder eine Blaupause.

Docker Container:

Eine laufende Instanz eines Images. Wie ein fertiges Gericht aus dem Rezept.

Dockerfile:

Eine Anweisungsdatei, die beschreibt, wie ein Image erstellt wird.

Docker Hub:

Eine Registry mit vorgefertigten Images (wie ein App Store für Container).

Erstes Docker-Beispiel

1. Dockerfile erstellen:

# Dockerfile
FROM node:14-alpine

WORKDIR /app
COPY package*.json ./
RUN npm install

COPY . .
EXPOSE 3000

CMD ["npm", "start"]

2. Image bauen:

docker build -t meine-app .

3. Container starten:

docker run -p 3000:3000 meine-app

Docker Compose für komplexe Anwendungen

docker-compose.yml Beispiel:

version: '3.8'
services:
  web:
    build: .
    ports:
      - "3000:3000"
  database:

Vorteile von Docker

✅ Vorteile

  • Konsistente Umgebungen
  • Schnelle Deployment
  • Einfache Skalierung
  • Ressourceneffizient
  • Microservices-freundlich
  • DevOps-Optimierung

❌ Nachteile

  • Lernkurve für Anfänger
  • Debugging komplexer
  • Persistent Data Handling
  • Sicherheitsaspekte
  • Performance-Overhead

Docker in der Praxis

Entwicklungs-Workflow:

  1. Lokal entwickeln: Container für isolierte Entwicklung
  2. Testen: Gleiche Umgebung wie in Produktion
  3. Deployment: Einfaches Ausrollen auf Servern
  4. Skalierung: Mehr Container bei Bedarf

Beliebte Docker-Anwendungsfälle:

  • Web-Anwendungen: Node.js, Python, PHP in Containern
  • Microservices: Jeder Service in einem eigenen Container
  • CI/CD-Pipelines: Konsistente Build-Umgebungen
  • Entwicklungsumgebungen: Gleiche Tools für alle Entwickler

Docker-Sicherheit

Best Practices:

  • Minimal Images: Nur nötige Dependencies
  • Multi-Stage Builds: Kleine Produktions-Images
  • Secrets Management: Keine Passwörter in Images
  • Regular Updates: Basis-Images aktuell halten
  • Resource Limits: CPU und RAM beschränken

Sicherheits-Kommandos:

# Container nicht als root ausführen
docker run --user 1000 meine-app

# Resource Limits setzen
docker run --memory=512m --cpus=0.5 meine-app

# Secrets übergeben (nicht in Image)
docker run -e DB_PASSWORD_FILE=/run/secrets/password meine-app

Docker vs Podman

Podman ist eine Docker-Alternative ohne Daemon:

  • Docker: Client-Server-Architektur mit Daemon
  • Podman: Daemonless, rootless möglich
  • Kompatibilität: Docker Compose läuft auch mit Podman

Fazit

Docker hat die Software-Entwicklung nachhaltig verändert. Containerisierung löst viele Probleme der traditionellen Software-Bereitstellung und ermöglicht moderne DevOps-Praktiken.

Zusammenfassung: Docker macht Anwendungen portabel, skalierbar und einfach zu verwalten. Die Lernkurve lohnt sich definitiv!
